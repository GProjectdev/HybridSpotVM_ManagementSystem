운영 감시 보완 2026-11-20 — 과학적 프로토콜 변경 없음

대상: 첫 GPT-2 A의 학습 완료 이후 정상 정리 중 observer heartbeat stale 및
삭제된 NodeRequest를 Control.policy()로 요구한 오류. 원본 Run과 formal_valid=false,
동결 Manifest/도구/학습 코드/이미지/위험 입력/목표 Step은 수정하지 않는다.

변경
- evaluation/operational_watch.py: 동결 watch를 별도 버전으로 가져왔다.
  학습 중90초 heartbeat, 연속2회 센서 실패, 비용/공간/동시VM/절대 종료 규칙 유지.
  formal-completion-observed.json의 모든 Rank 목표/완료 audit 및 동일 state hash를
  검증한 뒤 run_id/namespace/source UID/frozen SHA/ownership SHA/completion SHA에
  묶인 success-cleanup-phase-v1 receipt를 배타적·원자적으로 작성한다.
  이 receipt만으로 성공/정리 완료를 선언하지 않는다.
  정리 중에는 training Pod heartbeat 대신 fresh exact AWS instance observations,
  provider UID/정책 UID, 가격, NFS/로컬 공간, 비용, 종료시각을 계속 감시한다.
  source 부재는 검증된 정리 단계에서 허용하고 재생성된 다른 UID는 거부한다.
  AWS NOT_OBSERVED는 종료가 아니며 현재 ledger의 지연/누락/unknown/foreign을 거부한다.
  EC2 terminated만으로 EBS/ENI/keypair 정리 성공을 추정하지 않는다.
- integrated_control.Control.quiesce: 성공 증거가 있으면 첫 삭제 전에 위 receipt를
  자동 바인딩한다. 증거가 잘못돼도 기존 정상 abort cleanup을 막지 않으며 감시는
  완화하지 않는다. 기존 UID precondition, finalizer, source cleanup 동작은 유지한다.
- ieee_v2_observe.py: deleting/Pending Pod의 로그 RPC를 명시적으로 생략한다.
  Running/Unknown 및 Succeeded/Failed의 마지막 audit 로그 수집은 유지한다.
  capture 시작/완료 시각과 생략 이유를 남긴다. 같은 기존 로그 RPC의 전체 UTF-8
  응답은 private gzip frame(0700/0600)과 SHA로 보관한다. 중복 줄도 그대로 보존한다.
  공용 metric allowlist, RPC 10,000,000-byte 한도,15초 요청 간격은 바꾸지 않는다.
  저장된 응답의 무손실 보관과 Node 소실 후 미관측 로그의 존재는 구분한다.
- lossless_archive.py: 종료된 Run의 전체 파일을 비공개 gzip tar로 복사하고 모든
  파일의 SHA를 압축 해제 스트림과 대조한다. 파일 집합/inode/size/mtime/ctime
  안정성 및 로컬 공간 확인, 배타적 생성/fsync를 사용한다. 원본 삭제 기능은 없다.

적용
기존 frozen/runner 또는 이미 소비한 GPT-2 A workflow를 덮어쓰거나 재실행하지 않는다.
별도 operational-amendment/runner 사본의 observer/watch/Control을 함께 사용해야 한다.
정상 정리 전에 Control.quiesce가 success receipt를 자동 작성한다. 수동 호출 시:
  python3 <new-runner>/evaluation/operational_watch.py --directory <new-run-dir> \
    --authorization <new-run-dir>/authorization.json --repository <new-runner> --enter-cleanup
아직 새 GPU/FIS 실행 승인은 없으며, 이 명령 예시는 실행 승인이 아니다.
비용/가격 collector와 독립 cleanup watchdog는 부대 자원 정리 확인까지 유지한다.

재현(CPU만 사용, 저장소 root)
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s evaluation -p test_operational_watch.py -v
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s evaluation -p test_ieee_v2_observe.py -v
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s evaluation -p test_integrated_control.py -v
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s evaluation -p test_lossless_archive.py -v

연구 판정
원시 측정 검산과 정식 비교 적격 판정은 다르다. 기존 자동 flag를 바꾸지 않고 외부
연구자 판정/예외 근거를 별도 기록해야 한다. 이번 보완으로 과거 Run을 소급 통과시키지
않는다. 첫 A의 데이터가 유지되므로 학습을 임의로 다시 실행하지 않는다.

보관 정정
Checkpoint는 NFS가 원본 저장소다. Management에 선택 CP 사본을 모두 만드는 것은
필수 실험 조건이 아니다. Management 용량은 실제 계측 로그와 Run 원시 관측 자료를
기준으로 관리한다. NFS의 CP 공간 부족과 로컬 로그 보관 예산을 혼동하지 않는다.
기존 CP/로그 삭제, 스토리지 생성/확장, sampling 간격 변경은 수행하지 않았다.
원시/private gzip 파일 및 TLS/AWS 인증 관련 실행 자산은 Git에 올리지 않는다.
