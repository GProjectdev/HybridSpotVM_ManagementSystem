0. 결론과 변경 범위

기존 연구 질문과 A/B/C 비교군은 유지한다. GPT-2 Small 4,800 Step과 ResNet-50
26,700 Step은 임의의 수용검사 목표가 아니라, 실측 처리율·기동·Checkpoint pause·
교체 준비와 native 1시간 위험 입력/50% FIS 조건을 결합한 후보라는 근거가 있다.
다만 GPT-2 시간창은 좁고 과거 느린 표본에서는 충돌하므로, 보장된 설정이라고
표현할 수 없다. 아래 시간창과 운영상 한계를 연구자가 확인한 뒤에만 동결한다.

현재 합의는 조건당 1회, 모델 2개 × A/B/C = 고유 6 Run이며 탐색적 평가다.
반복 간 편차나 통계적 유의성은 산출할 수 없다. 반복 확대 권고와 기존 합의를
구분했다. 이미 검증한 GPU/Restore/FIS 기능은 재사용하고 중복 실행하지 않았다.
이번 검토에서 새 GPU 생성, FIS, 컨트롤러·이미지·스토리지 변경은 하지 않았다.
오프라인 집계 도구와 실행 문서만 보완했다. 긍정적 결과를 보장하지 않는다.

실험이 새롭게 입증하려는 것은 위험률 알고리즘 자체가 아니라 다음 통합의 효과다.
Karmada 원본 요청 → 정책 계산 → GPU Worker 준비/배치 → 전체 DDP Checkpoint →
위험 변화 또는 실제 Spot 중단 → 소유권/소스 fencing을 지킨 그룹 복원 → 모든
Rank 업데이트 재개 → 과거 진전 회복 → 목표 완료 → 실제 VM 반환까지의 운영이다.

1. 비교군과 연구 질문: 유지한 설계와 주장 가능한 범위

모든 기본 비교는 모델별 4-Rank, 서로 다른 4개 VM, VM당 GPU 1개/Rank 1개다.
E1: A=4 On-Demand, 주기 Checkpoint 비활성, 계획 장애 없음.
    B=기존 위험률·가격 정책과 Checkpoint 조율, 정책 교체 가능, 계획 장애 없음.
E2: A/B는 완전히 동일한 계약·원시 증거인 경우에만 E1 자료를 재사용한다.
    C=B와 동일한 설정/위험 입력, 최초 소유 Spot Worker 1개에 FIS 1회.
    FIS는 목표의 50% 공통 유효 Step, PT2M 통지, 대상 재선정 금지다.

E1의 질문: 같은 학습량을 요청부터 완료·반환까지 운영했을 때, 통합 방식 B가
All-OD A보다 어떤 GPU 비용–완료시간 관계를 갖는가? 비용 감소뿐 아니라 추가
Checkpoint/교체/rollback/중첩 VM 비용과 성능 저하도 함께 보여야 답할 수 있다.
주 지표: C_B/C_A, (C_A-C_B)/C_A, T_B-T_A, T_B/T_A, 유효 처리율,
완료 여부, 저장 횟수·pause, 실제 구성 변화·그룹 복구·반환 지연.
이는 전체 패키지 비교다. A에는 계획 장애를 주지 않으므로 A와C가 동일한 장애
서비스 수준을 보장받는다는 실험은 아니다. 통제한 운영 시나리오의 비용–성능 비교다.
Spot 할인, 자원 정책, Checkpoint 주기의 각각 독립적인
인과 효과를 분리한 실험은 아니다. 별도 ablation을 이번에 임의로 추가하지 않았다.

E2의 질문: 단일 Spot 중단을 실제로 겪은 C의 운영 시간·비용은 B보다 얼마나
달라지며, 그런 부담까지 포함해도 같은 규모의 A 대비 경제성이 남는가?
주 지표: ΔT_fault=T_C-T_B, ΔC_fault=C_C-C_B, (C_A-C_C)/C_A,
실제 중단·무진전·새 VM 준비·Restore·전체 업데이트 재개·재학습 시간,
전체 목표 완료 및 모든 과거 소유 VM의 종료 확인.
Δ는 부호를 보존한다. 긴급 Checkpoint가 더 신선해서 C의 rollback이 B보다 작으면
ΔT/ΔC가 음수일 수도 있다. 이를 제거하거나 무조건 양의 복구비용으로 고치지 않는다.

중요한 해석 제한: 두 조건은 동일한 정책 입력을 사용하지만 서로 다른 실제 시각의
클라우드 실행이다. AWS 가격·용량·기동 지연은 같다고 보장하지 못한다. 특히 C 복구가
1시간 위험 전환 뒤까지 이어질 수 있어, C-B는 장애와 후속 정책의 상호작용까지
포함한 순운영 차이다. 순수 Restore 엔진의 독립적인 인과 비용으로 해석하지 않는다.
같은 Rank·모델 내에서만 비교하며, GPT 토큰/ResNet 이미지 또는 2/4-Rank 결과를
합쳐 하나의 성능·비용 비율로 만들지 않는다.

측정된 C_A-C_B가 정상 운영의 비용 여유다. 동일계약에서 ΔC_fault<C_A-C_B이면
관측된 단일 선점 C도 A보다 GPU 가격추정상 저렴하다. 음수/0인 여유도 그대로 보고한다.
동일 노출길이/계약의0회·1회 사건만 가정한 보조 시나리오는 C(p)=C_B+p(C_C-C_B).
ΔC_fault>0일 때 p<(C_A-C_B)/ΔC_fault가 산술 손익분기 조건이다. 범위를 벗어나는
p와 Δ<=0은 별도 해석한다. 이 p를 자연 선점확률로 추정하거나 여러 중단의 선형
법칙으로 확대하지 않는다. proxy λ로 실제 서울 기대 절감률을 계산하지 않는다.

기대 가능한 이점(아직 미측정): Spot 사용 구간의 낮은 단가, 갱신된 위험에 따른
구성 반영, 요청부터 반환까지 자동 운영, 단일중단 후 진전/데이터 순서 보존,
배치 준비와 byte-identical 재쓰기 생략으로 불필요한 반복 작업 감소 가능성.
추가 부담: 기동/전파/whole-world pause, 병렬 대체 VM 비용, NFS I/O/compare 읽기,
Checkpoint 저장·동기화, 오래된 CP rollback, 데이터/그룹 재개, OD 최소유지와 반환대기.
이전 수용검사의 중복쓰기0이라는 계측은 end-to-end speedup 증명이 아니다.
저위험 긴 interval(실측 GPT20030/R5011065초)은1시간 교체 시 오래된 CP를 골라
많은 진전을 되돌릴 수 있다. 실제로 비용이 A보다 높아질 가능성을 숨기지 않는다.
cutover 직전 신규 CP 같은 큰 프로토콜 변경은 이번에 추가하지 않았다.
