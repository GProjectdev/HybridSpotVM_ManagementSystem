서버 Codex 추가 지시 — 통합 정량 평가 수정 v2 (2026-11-18)

이번 대화에서 확정한 'HybridSpotDDP_통합정량평가_수정실험명세_v2_20261118.txt'를 반드시 먼저 읽고, 기존 계획과 충돌하는 모든 Rank 수/초기 GPU 구성/Run 수/비교·해석 항목을 v2 기준으로 정합성 있게 업데이트하라.

가장 중요한 변경:
1) S1 정상 위험 변화 평가를 2-Rank 초기 1OD+1Spot 고정에서 '4-Rank, targetWorkers=4, 위험·가격 기반 초기 Spot/OD 구성 선정'으로 변경한다. 최소 OD=1 제약하의 네 가지 가능한 혼합/OD 조합을 검토하지만, 실제 정책이 선택하지 않은 비율을 임의 강제하지 않는다.
2) S1-P0와 S1-P1은 같은 최초 정책 결정의 실제 초기 VM 비율을 공통으로 사용한다. 이후 P0는 자원 구성·CP 주기 고정, P1은 위험 기반 VM 재구성 및 CP 조율을 실행한다. 이 pair의 효과는 '동일 초기 구성에서 실행 중 적응 여부'이지 '초기 비율 선택의 독립적 최적성'이 아니다.
3) S2 Spot FIS 중단/복구는 기존대로 2-Rank=1OD+1Spot, P0/P1 × 정상/단일 Spot 중단의 2×2 구성. S2는 실제 공동 Spot 노출이 보장되는 입력을 사용한다.
4) S1 4-Rank와 S2 2-Rank는 직접 비용/완료시간을 합산하거나 S1 전환비용+S2 복구비용으로 손익분기 확률을 산출하지 않는다. 해당 주장을 보존한 기존 보고서/스크립트/그래프 예시는 수정 또는 무효 표시한다.
5) S1에서 주 모델 GPT-2의 동일 global batch8을 유지한다면 rank별 batch2(4rank)를 사전 수용 검토하고, ResNet은 global64/rank별16 후보로 본다. batch/target step/optimizer/model-data contract를 고정한다.
6) S1 4-Rank CP/Full-group Restore, 일시적 VM 중첩·GPU Spot/OD Quota, NFS archive 저장량과 FIS 관련 2-Rank 경로는 각각 독립적으로 확인해야 한다. 4-Rank가 된다는 것을 미리 주장하지 마라.

기존 재검증 방지:
- GPT2 과거 FIS/restore, ResNet 동일 Pod C/R, G6 2Rank durable CP, Collector TLS, SARIMA trace/forecast, Go policy probe, 학습 데이터·모델 해시는 이미 보유한 원본·버전·UID로 확인하라.
- 동일 환경/버전에서 검증 완료된 항목은 무의미하게 재실행하지 마라.
- 그러나 4-Rank group CP/새 VM 복원, FIS 수정 후 실제 권한·중단, Spot capacity, S1 적격 위험률 구간은 기존 자료로 미검증이면 반드시 보고하고 최소 수용검사를 설계하라.
